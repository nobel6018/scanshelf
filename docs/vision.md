# 이미지 처리 (scanshelf-vision)

코드: `crates/scanshelf-vision/`. 입력과 출력은 `image::RgbImage`이고 macOS API를 쓰지 않습니다. 모델은 ONNX Runtime(`ort`)으로 돌리고, macOS에서는 CoreML 실행기를 붙입니다. Windows로 넓힐 때 바꿀 곳은 실행기 선택(`models.rs`의 `load`)뿐입니다.

원근 보정(`perspective.rs`)은 mac-pipeline 담당이고, 이 문서는 그 뒤 단계를 다룹니다.

## 처리 순서

`pipeline::process_source`가 원근 보정이 끝난 사진 한 장을 출력 페이지 한 장, 두 장(펼친 책), 세 장(3단 접지)으로 만듭니다.

| 순서 | 단계 | 함수 | 이유 |
|---|---|---|---|
| 1 | 손가락 지우기 | `fingers::remove_fingers` | 손은 사진 테두리에서 들어온다. 나누기 전 원본에서 찾는다. 플랫폼 손 마스크도 원본 좌표다 |
| 2 | 두 페이지 분리, 세 면 분리 | `split::split_spread`, `fold::split_trifold` | `PageLayout::Spread`, `PageLayout::Trifold`일 때만. 신뢰도가 낮으면 통째 한 장으로 둔다 |
| 3 | 곡면 보정 | `dewarp::dewarp` | 페이지마다. 접힌 선 그림자가 한쪽 끝에 있어야 모델이 페이지 경계를 잡는다 |
| 4 | 필기 지우기 | `handwriting::remove_handwriting` | 펴진 뒤라 획이 덜 휘고, 조명 보정 전이라 원래 색이 남아 있다 |
| 5 | 조명 보정, 필터 | `filter::apply_filter` | 마지막 |

`process_page`는 나눠진 페이지 하나에 3~5단계만 겁니다. 단계별 걸린 시간은 `PageReport::timings`, `SourceReport::timings`에 남습니다. 찾은 접힌 선은 `SourceReport::gutter`(펼친 책), `SourceReport::folds`(3단 접지)에 남습니다.

## 공개 함수

| 함수 | 하는 일 |
|---|---|
| `process_source(img, layout, &ProcessOptions, finger_mask, &Models)` | 전체 흐름. `Vec<ProcessedPage>`(part, image, report)와 `SourceReport` |
| `process_page(img, &ProcessOptions, &Models)` | 곡면 보정, 필기 지우기, 필터 |
| `find_gutter(img) -> Gutter` | 접힌 선(위쪽 x, 아래쪽 x, 신뢰도, 그림자 깊이, 빈 띠 폭) |
| `split_spread(img) -> Split` | `Spread { left, right, gutter }` 또는 `Single { gutter }` |
| `split::cut(img, &Gutter)` | 주어진 접힌 선으로 자르기(화면에서 사용자가 선을 고쳤을 때) |
| `find_folds(img) -> Folds` | 3단 접지의 접힌 선 두 개(선마다 위쪽 x, 아래쪽 x, 신뢰도, 자국 세기, 빈 띠 폭)와 전체 신뢰도 |
| `split_trifold(img) -> Trifold` | `Panels { panels: [왼쪽, 가운데, 오른쪽], folds }` 또는 `Whole { folds }`. 면 폭이 모두 28~38%가 아니면 1/3, 2/3 근처(28~39%, 61~72%)만 다시 찾는다. 한 선이 0.9 이상이고 면 폭이 고르면 다른 선은 0.2만 돼도 받는다 |
| `snap_folds(img, hints) -> Vec<Fold>` | 사람이나 AI가 고른 위치(0~1) ±`SNAP_RANGE`(0.03) 안의 접은 자국에 붙인다. 자국이 약하면 준 위치를 세로선으로 |
| `cut_at(img, folds) -> Vec<RgbImage>` | 선 여러 개(왼쪽부터)로 자른다. 기운 선은 면마다 사다리꼴을 직사각형으로 편다 |
| `fold::cut_panels(img, &Folds)` | 주어진 두 선으로 세 면 자르기 |
| `dewarp(img, Dewarp, &Models) -> DewarpResult` | 곡면 보정. 모델이 없거나 `Off`면 입력 그대로, `applied = false` |
| `apply_filter(img, Filter)` | `Original`, `Enhanced`, `Grayscale`, `BlackWhite` |
| `detect_fingers(img) -> (mask, count)` | 테두리에 닿은 피부색 영역 마스크 |
| `remove_fingers(img, Option<&GrayImage>, &Models)` | 손가락 찾기, 외부 마스크 합치기, 메우기 |
| `detect_colored_ink(img)`, `remove_handwriting(img, &Models)` | 색 펜 자국 찾기, 지우기 |
| `inpaint(img, mask, &Models) -> (image, InpaintEngine)` | 마스크(255 = 지울 곳) 메우기. LaMa, 없으면 고전 보간 |
| `Models::new(dir)`, `Models::none()`, `models::verify(path, spec)` | 모델 폴더 지정, 모델 없이 쓰기, 내려받은 파일 확인 |

## 모델

모델 파일은 저장소에 넣지 않습니다(크기, 라이선스). 목록은 `models::MODELS`에 있고, 앱이 처음 쓸 때 GitHub 릴리스(`models-v1`)에서 받아 모델 폴더에 둡니다. 내려받기는 앱 쪽 `src-tauri/src/download.rs`(조각 이어 받기)가 하고, 받은 뒤 `models::verify`로 크기와 SHA-256을 확인합니다. 이 크레이트는 네트워크를 쓰지 않습니다.

| 파일 | 크기 | SHA-256 | 출처 | 라이선스 | 실행기 |
|---|---|---|---|---|---|
| `uvdoc.onnx` | 31,602,475 | `ba42385a7f881afabc67ca6c4cc854d1506c52b94ee9af4e35261ddf347cea1d` | UVDoc(tanguymagne/UVDoc, 커밋 `4c9b82b`) | MIT | CoreML, 실패하면 CPU |
| `lama_fp32.onnx` | 208,044,816 | `1faef5301d78db7dda502fe59966957ec4b79dd64e16f03ed96913c7a4eb68d6` | big-lama의 ONNX 변환(Carve/LaMa-ONNX, 커밋 `c3c0c9e`) | Apache-2.0 | CPU |

`export_uvdoc.py`는 커밋과 가중치 해시를 고정하고, 내보낸 ONNX 출력이 PyTorch와 같은지(최대 차이 1.3e-6) 확인합니다. 두 번 내보내면 바이트 단위로 같은 파일이 나옵니다.

### 실행기 선택에서 알아 둘 것

- `ort`는 실행기를 지정하지 않으면 macOS에서 CoreML을 자동으로 붙입니다(`AutoDevicePolicy` 기본값). 그래서 CPU 경로에는 `PreferCPU`를 명시합니다. 이걸 빼면 CPU라고 표시되면서 실제로는 CoreML(fp16)로 돌고, LaMa는 세션 준비에 12~16초가 걸립니다
- CoreML은 `MLProgram` 형식으로 붙이고, 컴파일 결과를 모델 폴더의 `coreml-cache/`에 남깁니다
- LaMa는 CoreML로 돌려도 CPU보다 빠르지 않아(512 입력 한 번 1.1~1.2초로 같음) 세션 준비가 짧은 CPU를 씁니다
- release 빌드(LTO)에서 CoreML 실행기가 쓰는 `__isPlatformVersionAtLeast`를 못 찾아 링크가 깨집니다. `build.rs`가 `libclang_rt.osx.a`를 붙여 해결합니다

## 단계별 방법

### 두 페이지 분리 (`split.rs`)

긴 변 1000화소로 줄인 휘도에서, 기울기 -8도~8도(0.5도 간격)마다 기울어진 세로선을 따라 두 단면을 냅니다.

- 밝기 단면: 가운데 25~75% 안에서 양옆 어깨보다 가장 깊이 파인 골짜기(접힌 선 그림자)
- 잉크 단면: 가운데 30~70%를 지나는 글자 없는 가장 넓은 띠(그림자가 약한 사진용)

두 단서 중 강한 쪽이 큰 기울기를 고릅니다. 빈 띠가 뚜렷한데 골짜기가 그 밖이면 띠를 믿습니다. 펼친 책은 가로가 길어서, 세로로 긴 사진은 신뢰도를 깎습니다. 신뢰도가 `MIN_CONFIDENCE`(0.35) 미만이면 `Split::Single`입니다. 자를 때는 접힌 선이 세로가 되게 돌린 뒤 자릅니다.

### 세 면 나누기 (`fold.rs`)

3단 접지 팜플렛을 펼쳐 한 장에 찍은 사진(`PageLayout::Trifold`)을 왼쪽부터 세 면(`PagePart::Panel(0..=2)`, 출력 id `-P1`~`-P3`)으로 나눕니다. 두 페이지 분리를 넓힌 방법이고, 다른 점은 셋입니다.

- 선이 두 개입니다. 폭의 20~47%, 53~80% 두 구간에서 따로 찾고, 1/3과 2/3에서 멀수록 점수를 조금(구간 끝에서 절반) 깎습니다. 안으로 접혀 들어가는 면은 2~3mm 좁아 면 폭이 정확히 같지 않습니다
- 단서가 약합니다. 책 가운데 같은 넓은 그림자가 없어서, 글자 화소(종이 밝기 60% 미만)를 뺀 종이 밝기 단면에서 세 가지를 봅니다. 가는 골짜기(어두운 접은 자국), 가는 봉우리(빛 받은 자국), 밝기 계단(면마다 빛 받는 각도가 달라 생김, 0.6배). 폭 1000 기준 좌우 8화소 창입니다
- 원근이 남아 두 선의 기울기가 다를 수 있습니다(사다리꼴). 선마다 기울기를 -6도~6도, 0.25도 간격으로 따로 찾습니다. 접은 자국은 2~3화소 폭이라 두 페이지 분리(0.5도)보다 촘촘합니다

사진(팜플렛 그림) 가장자리도 밝기 계단을 만듭니다. 접은 자국은 위에서 아래까지 이어지므로 높이를 네 띠로 나눠 띠마다 점수를 내고, 네 띠 중 둘째로 약한 값을 씁니다(세 띠 이상에서 보여야 함). 자국도 계단도 없으면 두 면 여백이 만나는 글자 없는 세로 띠(이미지 끝에 닿지 않는 것)로 찾습니다.

선 하나의 신뢰도는 자국 신뢰도(종이 밝기 대비 1.2%에서 0, 5.2%에서 1)와 빈 띠 신뢰도(폭 1.2%에서 0, 4.2%에서 0.8) 중 큰 쪽에 작은 쪽의 1/4을 더한 값입니다. 자국 신뢰도가 0.5 이상이면 자국 위치를, 약하면 빈 띠 가운데를 씁니다(면 여백은 양쪽이 다를 수 있어 자국이 더 정확). 전체 신뢰도는 두 선 중 약한 쪽 x 가로세로 비 조건(가로/세로 0.85 미만이면 0.2까지 깎음) x 면 폭 조건(세 면 모두 폭의 20~46%가 아니면 0.3배)이고, `MIN_FOLD_CONFIDENCE`(0.35) 미만이면 나누지 않고 통째 한 장(`Trifold::Whole`, `PagePart::Whole`)으로 둡니다.

자를 때 두 선이 세로면 그대로 자르고, 기울었으면 면마다 네 꼭짓점(위아래 선 끝)을 원근 보정(`perspective::warp_to_size`, 쌍삼차)으로 직사각형으로 폅니다. 면 폭은 위아래 폭의 평균입니다.

### 곡면 보정 (`dewarp.rs`)

UVDoc이 488x712 입력에서 45x31 역방향 격자(출력 각 점이 원본 어디인지)를 예측합니다. 격자를 출력 해상도로 늘려 원본 고해상도 사진에서 직접 표본을 뜹니다. 모델 해상도로 펴서 늘리는 것보다 글자가 선명합니다. 출력 크기는 격자 가로줄, 세로줄의 원본 위 길이로 정해 펴진 페이지의 원래 비율이 돌아오고, 원본보다 화소 수가 늘지 않게 맞춥니다.

모델은 바탕 위에 놓인 페이지 사진을 보고 페이지 경계를 찾도록 학습됐습니다. 꼭짓점으로 이미 잘라 낸 페이지를 그대로 넣으면 글자 덩어리 가장자리를 경계로 보고 둘레를 잘라 냅니다. 2026-11-08 보관함 68쪽에서 재 보니 한 변이 평균 6%, 최대 25%까지 잘려 제목과 쪽 번호가 사라졌습니다. 그래서 입력 모양(`Framing`)을 받습니다.

| `Framing` | 언제 | 1차 예측 |
|---|---|---|
| `Page` | 꼭짓점으로 원근 보정한 페이지(앱 기본) | 둘레에 어두운 바탕을 붙여 예측(`predict_padded`). 잘린 변 1% 안쪽 |
| `Photo` | 꼭짓점 없이 사진 전체 | 그대로 예측. 모델이 페이지 경계도 찾아 책상을 덜어 낸다 |

앱은 `steps.rs` `correct_page`가 쓴 꼭짓점이 있으면 `Page`, 없으면 `Photo`를 넘깁니다. 시험: `tests/synthetic.rs` `잘라_낸_페이지는_곡면_보정이_둘레를_자르지_않는다`.

`Strong`(vFlat "더 펴기")은 한 번 편 결과(모델 입력의 2배 해상도)를 다시 모델에 넣어 남은 굽음을 잡고, 두 격자를 합성해 원본에서 한 번만 표본을 뜹니다. 2차 입력에는 둘레에 어두운 바탕(6%)을 붙입니다. 안 붙이면 페이지가 화면을 꽉 채워 모델이 글자 덩어리 가장자리를 페이지 경계로 보고 여백을 잘라 냅니다.

### 조명 보정과 필터 (`filter.rs`)

- `Enhanced`: 긴 변 기준 64개 블록마다 밝은 화소(상위 8%) 색을 배경으로 잡습니다. 중앙값이 너무 어둡거나(사진, 굵은 제목) 채도가 높은 블록은 종이가 아니라서 둘레 종이 블록에서 pull-push로 메웁니다. 채널마다 배경으로 나누므로 그림자 제거와 흰색 맞춤이 한 번에 되고, 사진 영역은 주변 종이와 같은 비율로 밝아져 색이 날아가지 않습니다. 마지막에 수준 맞춤(검정 22, 흰색 246)으로 대비를 조금 올립니다. 종이 전체가 색지면 채도 조건을 풉니다
- `Grayscale`: `Enhanced` 뒤 휘도
- `BlackWhite`: `Enhanced` 휘도에 Sauvola(k 0.18, R 128, 창 한 변이 긴 변의 약 4%). 지역 평균과 표준편차는 긴 변 1200 축소 영상에서 구해 늘립니다
- `Original`: 그대로

### 손가락 지우기 (`fingers.rs`)

긴 변 512로 줄여 종이(밝은 10%) 색으로 흰색을 맞춘 뒤, YCrCb 피부색(Cr 138~178, Cb 77~130, Cr-Cb 15 이상)을 고릅니다. 열림, 닫힘으로 잡티를 지우고 이미지 테두리에 닿은 덩어리(면적 0.15~25%)만 남깁니다. 반그림자까지 덮게 넓혀 원본 크기로 늘리고 메웁니다. 플랫폼 쪽(iPhone Vision 손 인식 등) 마스크를 주면 합칩니다.

### 필기 지우기 (`handwriting.rs`)

종이 배경으로 나눈 색에서 채도(최대-최소 채널) 50 이상이고 종이보다 어두운 화소를 색상각으로 파랑(190~270도), 빨강(330~20도), 초록(80~170도)에 나눕니다. 면적이 0.2% 이상이고 외곽 상자를 55% 이상 채운 덩어리(인쇄된 색 상자, 로고)는 남깁니다. 기본값은 꺼짐입니다.

### 메우기 (`inpaint.rs`)

마스크 영역마다 긴 변 절반(최소 32화소) 여백을 붙인 조각을 만들고 겹치면 합칩니다. LaMa는 512 고정 입력이라, 한 변이 1024보다 큰 조각은 768 타일(128 겹침)로 나눠 차례로 메웁니다(앞 타일 결과가 다음 타일 문맥). 줄였다 늘린 결과는 종이 색이 어긋나서 마스크 밖 평균 차이만큼 옮겨 붙이고, 경계는 2화소 부드럽게 섞습니다.

모델이 없으면 pull-push 보간으로 메웁니다. 둘레의 글자 화소를 섞으면 회색 얼룩이 되므로 종이 밝기(상위 10%)의 75%보다 어두운 화소는 빼고 메웁니다.

## 평가

`crates/scanshelf-vision/tests/synthetic.rs`. 실제 책이나 스캔은 쓰지 않습니다. 시스템 글꼴(Times New Roman, Arial, DejaVu)이 있으면 뜻 없는 낱말로 페이지를 그리고, 없으면 낱말 크기 막대로 대신합니다. 원통형 굽음, 접힌 쪽 그림자, 손가락(타원), 색 펜 물결선을 합성해 넣습니다.

```sh
cargo test -p scanshelf-vision                                   # 모델 없이 도는 시험
SCANSHELF_MODELS_DIR=~/leedo/scanshelf-models cargo test -p scanshelf-vision --release --test synthetic          # 모델 시험 포함
SCANSHELF_MODELS_DIR=~/leedo/scanshelf-models SCANSHELF_EVAL_OUT=/tmp/scanshelf-eval \
  cargo test -p scanshelf-vision --release --test synthetic -- --ignored --nocapture                  # 전후 이미지와 속도
SCANSHELF_MODELS_DIR=~/leedo/scanshelf-models cargo run -p scanshelf-vision --release --example bench            # 단계별 시간
```

지표는 두 가지입니다. 글줄 뾰족함은 이진화한 뒤 가로 행별 잉크 수의 표준편차/평균이고, 글줄이 곧을수록 큽니다. SSIM은 평평한 원본과 가로 400으로 맞춰 비교하는데, 보정 결과는 페이지 경계에 맞춰 잘리고 비율이 조금 달라 정렬 오차가 섞이므로 참고 값입니다.

### 결과 (2026-11-05, Apple M5 Pro 18코어)

| 항목 | 휜 입력 | 보정 | 더 펴기 | 평평한 원본 |
|---|---|---|---|---|
| 글줄 뾰족함(1200x1650 페이지) | 0.98 | 1.45 | 1.54 | 1.71 |
| SSIM | 0.34 | 0.44 | 0.40 | 1 |

- 두 페이지 분리: 기울기 0, 2.5, -3도 합성 펼침면에서 위치 오차 10화소 미만, 기울기 오차 1도 이내. 한 페이지는 나누지 않음
- 세 면 나누기: 아래 표(`tests/trifold.rs`)
- 조명 보정: 왼쪽 그림자(밝기 차 60 이상)가 15 미만으로 줄어듦
- 손가락: 정답 마스크를 97% 이상 덮고, 넘친 면적은 2% 미만. 지운 뒤 다시 찾으면 0개
- 필기: 색 화소가 98% 이상 사라지고, 펜이 지나지 않은 검은 글자는 99.5% 이상 남음

## 한계

- 곡면 보정과 손가락, 필기 지우기는 vFlat 자체 모델이 아니라 공개 모델이라 같은 품질을 장담하지 못합니다. 합성 페이지로만 쟀고, 실제 사진 비교는 아직 안 했습니다
- 더 펴기는 합성 시험에서 글줄은 더 곧아졌지만 SSIM은 보정 한 번보다 낮았습니다(여백을 조금 더 자름). 실제 사진으로 확인이 필요합니다
- 손가락 아래 가려진 글자는 되살리지 못합니다. LaMa는 그럴듯한 획을 지어내고, 고전 보간은 종이색으로 메웁니다
- 피부색과 비슷한 살구색, 주황색 인쇄물이 테두리에 닿아 있으면 손으로 잘못 볼 수 있습니다. 장갑, 매우 어둡거나 밝은 피부, 강한 색 조명에서는 놓칠 수 있습니다. 이때는 플랫폼 손 마스크가 보완합니다
- 필기 지우기는 색 펜만 됩니다. 연필과 검은 펜은 인쇄 글자와 색으로 구별할 수 없습니다. 파란 제목처럼 가는 색 인쇄 글자는 펜과 같이 지워지고, 형광펜(노랑)은 글자를 덮고 있어 지우지 않습니다. 넘으려면 손글씨 분할 모델이 필요합니다
- 펜이 글자 위를 지나간 자리는 글자 획이 흐려지거나 지어낸 모양이 됩니다
- `Enhanced`는 잘린 가장자리에 걸친 좁고 진한 접힌 선 그림자를 다 걷지 못하고 옅은 띠가 남을 수 있습니다
- 세 면 나누기는 합성 사진으로만 쟀습니다. 실제 팜플렛에서 자국 세기, 광택지 반사, 면을 가로지르는 큰 사진이 어떻게 나오는지는 확인하지 않았습니다. 그림이 접힌 선을 넘어 이어지는 팜플렛(펼침 그림)은 네 띠 중 둘 이상이 가려져 자국을 못 찾을 수 있고, 그때는 통째 한 장으로 남습니다
- Z 접지(병풍 접기)는 따로 시험하지 않았고, 4단 이상 접지는 다루지 않습니다

## 두 쪽 나누기의 위치 판단

실제 책자에서 그림자 골짜기와 글자 없는 빈 띠만 믿었더니 표의 칸 사이를 접힌 선으로 잡아 표와 제목을 잘랐습니다. 신뢰도까지 1.00으로 나왔습니다. 지금은 다음 순서로 판단합니다(`split.rs` `find_gutter`, `fold.rs` `find_center_crease`).

1. 글자를 뺀 종이 밝기의 골짜기가 깊으면(0.2 이상) 크게 휜 책으로 보고 가장 어두운 곳을 씁니다
2. 위에서 아래까지 이어지는 접은 자국이 뚜렷하면 그 선을 씁니다. 표의 칸 사이에는 자국이 없습니다
3. 자국이 약하면 얕은 골짜기로 범위를 좁히고 그 안에서 가장 뚜렷한 자국을 고릅니다
4. 그래도 없고 후보가 가운데에서 폭의 5%를 넘게 벗어나면 나누지 않습니다. 잘못 자르면 내용이 망가지고, 안 나누면 한 장으로 남을 뿐입니다

## 사진 영역 보정

보정(Enhanced)은 종이 배경으로 나눠 흰색까지 끌어올립니다. 사진까지 같이 올리면 밝은 부분이 하얗게 날아갑니다. 그래서 사진 영역을 찾아 밝기의 35%만 보정하고 수준 맞춤을 하지 않습니다(`filter.rs` `photo_mask`).

- 중간 톤이 45% 넘는 블록을 사진 후보로 잡습니다. 글자와 큰 제목은 종이와 잉크 두 덩어리라 빠집니다
- 사진 안쪽의 매끈한 면은 후보가 되지 않으므로 닫힘 연산으로 잇고 둘러싸인 곳을 채웁니다. 이 영역은 배경 추정에서도 뺍니다. 빼지 않으면 물체의 색을 종이로 알고 흰색으로 올립니다
- 사진 영역을 넓히지 않습니다. 넓히면 주변 종이가 덜 밝아져 회색 얼룩이 됩니다. 사진 블록 안이어도 종이만큼 밝은 화소는 종이로 다룹니다

## 실제 사진 확인 범위

| 자료 | 확인한 것 | 결과 |
|---|---|---|
| 거치대로 찍은 한국어 팜플렛 책자 1권(15장) | 회전, 두 쪽 나누기, 필터 | 눈으로 확인. 방향 오류 없음, 두 쪽 12장 모두 접힌 선에서 나눔(한 쪽으로 찍힌 1장 포함) |
| 공개 저작권의 펼친 책 사진 12장(손으로 든 각도 포함) | 회전 | 글자가 있는 9장은 바로 판단하고, 그중 8장은 90도 돌려도 일관됨. 세로쓰기 일본어 1장과 글자가 흐린 2장은 판단하지 않아 그대로 둠 |
| 같은 사진 | 접힌 선 | 정면에 가까운 펼침 3장은 접힌 선에 맞음. 비스듬한 사진은 테두리 감지가 어긋나 평가에서 뺌 |

거치대 없이 비스듬히 찍은 사진은 테두리 감지(원근 보정 단계)가 책을 잘못 잡을 수 있습니다. 세로쓰기는 읽는 방향이 달라 자동 회전이 판단하지 않습니다.
