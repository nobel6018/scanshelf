# 자동 촬영 설계 (iPhone)

거치대에 iPhone을 고정하고 종이만 바꿔 놓으면 한 장씩 찍히는 흐름이 목표입니다. 코드는 `ios/Scanshelf/Capture/`에 있습니다.

## 상태

```
대기 ─(문서 감지 + 화면 안정 + 손 없음)→ 촬영 ─→ 변화 대기 ─(내용이 바뀜)→ 대기
```

| 판단 | 방법 |
|---|---|
| 문서 감지 | Vision `VNDetectDocumentSegmentationRequest`. 미리보기에 테두리 표시. 화면 대비 넓이가 기준보다 작으면 문서로 보지 않는다 |
| 화면 안정 | 32x32 흑백으로 줄인 분석 프레임끼리의 평균 밝기 차이가 기준 아래로 일정 시간(보통 0.6초) 유지 |
| 손 없음 | `VNDetectHumanHandPoseRequest`. 손이 보이면 안정돼도 찍지 않는다. 종이를 내려놓는 손을 찍는 실수를 막는다 |
| 테두리 믿음 | 찾은 테두리가 사각형으로 믿을 만하지 않으면 "모서리를 찾는 중"으로 기다린다(`.unclearEdges`). 아래 "테두리를 믿을 수 있는가" |
| 화면 밖 | 꼭짓점이 화면 가장자리에 붙으면 종이 일부가 화면 밖이라 찍지 않는다(`.cutOff`, "종이 전체가 화면에 들어오게 놓아 주세요") |
| 같은 장 중복 방지 | 직전 촬영본과 `VNGenerateImageFeaturePrintRequest` 거리를 비교. 가까우면 같은 장으로 보고 건너뛴다 |
| 다시 놓은 같은 장 | 종이를 옮기거나 돌려 다시 놓으면 찍고, 앞 장을 지울지 묻는다. 아래 "같은 장을 다시 놓았을 때" |

변화 대기에서 대기로 돌아가는 조건은 문서가 사라짐, 손이 보임, 크게 움직임, 직전 촬영본과 거리가 멀어짐 중 하나입니다. 돌아간 뒤에도 찍기 직전에 중복 검사를 한 번 더 하므로, 종이를 들었다가 같은 장을 다시 놓으면 건너뜁니다. 직전 촬영본이 있는데 거리를 아직 못 쟀으면 찍지 않고 기다립니다(같은 장을 두 번 찍는 것보다 늦게 찍는 편이 낫다).

feature print는 프레임당 수십 ms라 필요할 때만 잽니다(`AutoCaptureEngine.wantsDistance`). 기준 프린트는 사진이 아니라 찍은 순간의 분석 프레임에서 만들어, 비교하는 두 쪽의 해상도가 같습니다.

수동 셔터를 누르거나 마지막 장을 지우거나 다시 찍기를 고르면 판단 상태를 맞춥니다(`manualCaptureStarted`, `forgetLastCapture`).

## 기준값

`ios/Scanshelf/Capture/AutoCapture.swift` `AutoCaptureTuning`. 설정의 민감도가 세 묶음 중 하나를 고릅니다. 모두 시작값이고 실제 문서, 책, 팜플렛으로 맞춥니다.

| 값 | 둔하게 | 보통 | 민감하게 | 뜻 |
|---|---|---|---|---|
| `stableDuration` | 1.0초 | 0.6초 | 0.4초 | 멈춘 상태가 이만큼 이어지면 찍는다 |
| `stillMotion` | 0.012 | 0.018 | 0.025 | 프레임 차이(0~1)가 이보다 작으면 멈춘 것 |
| `changeMotion` | 0.08 | 0.06 | 0.05 | 촬영 뒤 이보다 크게 움직이면 종이를 바꾸는 중 |
| `minimumDocumentArea` | 0.18 | 0.12 | 0.08 | 화면 대비 문서 넓이 하한 |
| `duplicateDistance` | 0.4 | 0.35 | 0.3 | 직전 촬영본과 이보다 가까우면 같은 장 |
| `changeDistance` | 0.6 | 0.55 | 0.5 | 촬영 뒤 이만큼 멀어지면 다른 장 |

그 밖의 값은 `FrameAnalyzer`에 있습니다: 문서 감지 신뢰도 0.5, 손 관절 신뢰도 0.5 이상 6개, 움직임 축소 크기 32. 분석 빈도는 `FrameThrottle.analysisFPS`(10)입니다.

## 테두리를 믿을 수 있는가

2026-11-08 박람회 팜플렛 21개(154장)를 찍었을 때 나온 문제와 처리입니다. 기준값은 `ios/Scanshelf/Capture/QuadGeometry.swift`(iPhone)와 `crates/scanshelf-core/src/lib.rs` `Quad::is_plausible`(Mac)에 같게 두고, 실제 촬영값 `fixtures/quad-plausibility.json`을 양쪽 테스트(`QuadGeometryTests`, `crates/scanshelf-core/tests/quad.rs`)가 읽습니다.

| 문제 | 실제 사례 | 판단 | 기준값과 근거 |
|---|---|---|---|
| 꼭짓점을 잘못 잡음 | 흰 면(빈 메모 쪽), 어두운 표지, 배경과 색이 비슷한 종이에서 Vision이 꼭짓점 한두 개를 접힌 선에 붙여 삼각형, 사다리꼴을 냈다(6장). Mac이 그대로 펴서 페이지가 찢긴 그림이 됐다 | 볼록, 마주 보는 변 길이 비(짧은 쪽/긴 쪽), 내각(`isPlausible`) | 변 비 0.8 이상: 정상 장 0.89 이상, 잘못 잡은 장 0.01~0.52. 내각 65~115도: 정상 84~96도, 잘못 38~167도. 길이와 각도는 세로 4:3 비율을 맞춰 잰다 |
| 화면 밖으로 나간 종이 | 3단 접지를 펼치면 화면 폭을 넘기 쉽다. 양옆이 잘린 채 찍히고, 고쳐 놓으면 또 찍혀 중복이 됐다(중복 3건 중 2건) | 꼭짓점이 가장자리에서 `edgeMargin`(0.01) 안 | Vision 테두리는 가로 1/144(약 0.007) 단위로 나오고, 화면 밖 종이는 0이나 0.007에 붙는다. 0.014에 놓인 정상 장이 있어 그보다 안쪽으로 둔다 |

- 촬영 판단(`AutoCaptureEngine.blockingStatus`)은 문서 없음, 손, 테두리 믿음, 화면 밖, 움직임 순서로 본다. 손을 먼저 보는 이유는 손이 종이를 가리면 테두리도 흔들려서다
- 사진을 저장할 때 사진에서 다시 찾은 테두리가 믿을 만하지 않으면 미리보기 테두리를, 그것도 아니면 테두리를 비워 둔다(`CaptureModel.capture`). Mac이 원본 해상도에서 다시 찾는다(docs/pipeline.md)
- 수동 셔터는 이 검사와 상관없이 찍는다. 책이 화면을 꽉 채우는 경우처럼 사람이 판단할 때를 위해서다

## 같은 장을 다시 놓았을 때

화면 전체의 feature print는 종이 위치와 각도에 따라 크게 달라진다. 그래서 테두리 안쪽만 원근 보정한 영역(`CIPerspectiveCorrection`)의 프린트도 잰다(`FrameAnalyzer.pagePrint`). 찍기 직전 안정을 기다리는 동안만 잰다(`AutoCaptureEngine.wantsPageDistance`).

직전 촬영 때와 비교해 꼭짓점이 `replacedShift`(화면 폭의 4%)보다 많이 움직였고 보정 영역 거리가 `duplicateDistance`보다 가까우면 `.captureRepeat`입니다. 새 장으로 찍고 8초 동안 "앞 장을 다시 놓았나요? 앞 장 지우기" 버튼을 띄웁니다(`CaptureModel.offerRepeat`, `deleteRepeatedPage`). 그대로 둔 같은 장은 지금처럼 전체 화면 거리로 건너뜁니다.

스스로 앞 장을 지우지 않는 이유(2026-11-08 실제 원본을 Mac Vision으로 잰 값, 긴 변 1440 축소):

| 쌍 | 보정 영역 거리 | 보정 영역 흑백 64px 상관 |
|---|---|---|
| 같은 장을 다시 놓음(중복 3건) | 0.244, 0.256, 0.295 | 0.81, 0.73, 0.79 |
| 레이아웃이 같은 다른 장(로보월드_1 7번과 8번, 사양표 카탈로그) | 0.273 | 0.80 |
| 다른 장 중 가장 비슷한 것(상관 기준, 로보월드_1 10번과 11번) | 0.428 | 0.97 |

같은 장과 비슷한 다른 장이 두 값 모두에서 섞여, 어떤 기준으로 자동 교체해도 진짜 페이지를 지울 수 있습니다. 그래서 찍는 쪽은 잃는 것이 없게 두고, 지우기는 사람이 고릅니다. 화면 밖 종이를 찍지 않게 하면서 오늘 중복의 대부분은 애초에 생기지 않습니다.

실기기 확인 필요: 위 거리는 Mac에서 사진을 줄여 잰 값이라 iPhone 분석 프레임 값과 다를 수 있습니다. `duplicateDistance`를 보정 영역 거리에도 그대로 쓰고 있으니, 같은 장을 옮겨 놓았을 때 버튼이 뜨는지, 다른 장에서 너무 자주 뜨지 않는지 보고 맞춥니다.

## 펼친 3단 접지

팜플렛은 배치를 3단(`trifold`)으로 고를 수 있습니다. 판단 흐름과 기준값은 한 장과 같습니다. 펼친 3단 접지는 가로로 긴 한 장(A4 가로 1.41:1, 레터 1.29:1)이라 비율로 거르지 않고, 넓이 하한만 봅니다.

세로 4:3 화면에 A4 가로 종이를 놓으면 폭을 다 채워도 높이는 화면의 53%라 넓이가 최대 약 0.53입니다. 폭의 80%면 약 0.34, 60%면 약 0.19로 가장 높은 하한(둔하게 0.18)보다 큽니다. 그래서 기준값을 바꾸지 않았고, 이 계산을 `AutoCaptureTests`(`펼친_3단_접지는_어느_민감도에서도_문서로_보고_찍는다`)로 고정했습니다. 화면 폭을 넘어 양옆이 잘리면 찍지 않습니다(위 "화면 밖으로 나간 종이"). 폭의 60%보다 작게 찍히면 둔하게에서는 찍히지 않으니 거치대를 올리거나 민감도를 보통으로 둡니다. 촬영 안내는 "3단 접지를 펼쳐 놓아 주세요"로 바뀝니다.

나누기(`-P1`~`-P3`)는 Mac이 합니다(docs/document-format.md).

## 좌표

manifest의 quad는 원본에 EXIF 회전을 적용한 뒤 기준 0~1이고 원점이 왼쪽 위입니다. 계산은 `ios/Scanshelf/Capture/QuadGeometry.swift`에 모으고 테스트(`QuadGeometryTests`)로 고정했습니다.

- 앱은 세로 고정입니다. 분석 버퍼는 센서 방향(가로) 그대로 두고 Vision에 `.right`를 넘겨, 결과가 세로 표시 방향 기준으로 나오게 합니다
- Vision 좌표는 원점이 왼쪽 아래라 y만 뒤집습니다(`QuadGeometry.fromVision`). 회전 뒤 꼭짓점 이름은 위치로 다시 붙입니다(`ordered`)
- 사진은 연결의 `videoRotationAngle`을 90으로 두고 찍어 EXIF 방향이 들어갑니다. 저장 뒤 사진에 EXIF 회전을 적용한 1600px 축소본에서 테두리를 다시 찾고(`FrameAnalyzer.detectQuad(inPhoto:)`), 못 찾으면 미리보기 테두리를 씁니다
- 세션 프리셋을 `.photo`로 두어 분석 프레임과 사진의 화각과 비율(4:3)이 같습니다. 미리보기도 4:3 상자에 `resizeAspect`로 그려, 테두리를 상자 크기에 그대로 곱하면 됩니다

## 셔터

- 자동 촬영을 끈 수동 모드도 둡니다(촬영 화면 오른쪽 위 "자동")
- 볼륨 버튼과 블루투스 카메라 리모컨: `AVCaptureEventInteraction`(iOS 17.2+). 시중 리모컨은 볼륨 키 신호를 보내므로 같이 처리됩니다. 뗄 때(`.ended`) 한 번 찍습니다(`ios/Scanshelf/Views/CameraPreview.swift`)
- 촬영은 `AVCapturePhotoOutput` 최대 해상도(`supportedMaxPhotoDimensions` 중 가장 큰 값), HEVC 코덱으로 HEIC를 저장합니다
- 찍히면 화면이 하얗게 번쩍이고 성공 진동이 옵니다. 실패하면 오류 진동과 안내 문구가 뜹니다
- 촬영 화면에 있는 동안은 화면이 꺼지지 않습니다(`isIdleTimerDisabled`)

## 시뮬레이터

시뮬레이터에는 카메라가 없어 `SyntheticFrameSource`가 코드로 그린 종이(어두운 책상, 흰 종이, 본문 줄)와 손을 10fps로 냅니다. 3초 놓여 있다가 1.5초 동안 손이 들어와 다음 장으로 바꿉니다. 저작권 자료는 쓰지 않습니다.

시뮬레이터 Vision은 문서 감지가 엉뚱한 띠를 내거나 비어 있고 feature print 거리도 실기기와 달라(2026-11-05 확인), 합성 소스가 주는 정답(테두리, 손, 장 번호)을 씁니다(`SyntheticHint`). 그래서 시뮬레이터에서는 판단 흐름과 화면만 확인되고 Vision 기준값은 확인되지 않습니다.
